F1命令注入漏洞：system() 拼接用户输入安全
src/mapOptmization.cpp:201-206, 437-439
saveMapService 中将 std::getenv("HOME") 与用户通过服务请求传入的 req->destination 直接拼接到 system("exec rm -r ...") 中执行。攻击者可通过构造 destination 参数（如 "; rm -rf /; #"）实现任意命令执行。
saveMapDirectory = std::getenv("HOME") + req->destination; int unused = system((std::string("exec rm -r ") + saveMapDirectory).c_str()); unused = system((std::string("mkdir -p ") + saveMapDirectory).c_str());
修复建议：1) 用 std::filesystem::remove_all() + std::filesystem::create_directories() 替代 system() 调用；2) 若必须用 system()，对路径做严格白名单校验（仅允许字母数字/下划线/斜杠）；3) 使用 execvp() 避免shell解释。
F2getenv("HOME") 返回 nullptr 导致未定义行为Bug
src/mapOptmization.cpp:201-202, 437
当 HOME 环境变量未设置时（如 Docker 容器、某些 systemd 服务环境），std::getenv("HOME") 返回 nullptr。nullptr + std::string 的拼接是未定义行为，会导致段错误崩溃。
saveMapDirectory = std::getenv("HOME") + savePCDDirectory; // nullptr + string = UB
修复建议：const char* home = std::getenv("HOME");
if (!home) home = "/tmp";
saveMapDirectory = std::string(home) + savePCDDirectory;
F3内存泄漏：ISAM2 原始 new 无 delete内存
src/mapOptmization.cpp:176
isam = new ISAM2(parameters) 使用裸 new 分配，但整个类没有析构函数释放该内存。程序退出时虽然 OS 会回收，但若 mapOptimization 被多次构造/析构（如单元测试），每次都会泄漏一个 ISAM2 对象。
isam = new ISAM2(parameters); // 无析构函数，无 delete isam;
修复建议：改用 std::unique_ptr<ISAM2>：
std::unique_ptr<ISAM2> isam;
isam = std::make_unique<ISAM2>(parameters);
或在类中添加析构函数 ~mapOptimization() { delete isam; }

imuIntegratorImu_ 和 imuIntegratorOpt_ 使用裸 new 分配，IMUPreintegration 类无析构函数释放。每次节点重启都会泄漏。

F5内存泄漏：imageProjection 四个裸数组无 delete[]内存

imuTime, imuRotX, imuRotY, imuRotZ 使用 new double[queueLength] 分配，但 ImageProjection 类无析构函数释放。每个数组 2000 个 double = 16KB，合计 64KB 泄漏。

C3semantic_bridge.py 性能瓶颈：逐点 Python 循环性能
semantic_bridge/semantic_bridge.py:40-63
对每帧点云（Ouster OS1-64 约 131072 点）逐点用 struct.unpack_from 解析 + struct.pack 打包。Python 逐点循环处理 13万点预计耗时 500ms+，远超 10Hz 帧率要求（100ms/帧），会导致严重丢帧。
for i in range(num_points): offset = i * point_step x = struct.unpack_from('f', msg.data, offset)[0] y = struct.unpack_from('f', msg.data, offset + 4)[0] z = struct.unpack_from('f', msg.data, offset + 8)[0] intensity = struct.unpack_from('f', msg.data, offset + 12)[0] # ...逐点打包 new_data.extend(struct.pack('f', x))
修复建议：用 NumPy 向量化替代逐点循环（参考 cylinder3d_ros_node.py 的 _parse_ouster_cloud 和 _build_semantic_cloud_msg 方法），性能可提升 100 倍以上。

C5saveMapService 中 system("exec rm -r") 无路径校验安全
src/mapOptmization.cpp:205
system("exec rm -r " + saveMapDirectory) 中 saveMapDirectory 由用户输入 + HOME 拼接。若路径中包含空格或特殊字符，rm -r 可能删除意外目录。虽然与 F1 相关，但这里额外强调 rm -r 的危险性——即使无恶意输入，路径 /home/user/my path/ 中的空格会导致 rm -r /home/user/my 和 path/ 分别执行。
修复建议：1) 用 std::filesystem::remove_all() 替代 system("rm -r")；2) 至少对路径加引号：system("rm -r '" + saveMapDirectory + "'")（但仍有注入风险，优先用方案1）。

W4热循环中使用 cv::Mat::at<float>() 访问性能

在 LMOptimization 的内循环中，每行调用 7 次 matA.at<float>(i, j) 和 matB.at<float>(i, 0)。.at<>() 每次都做边界检查，在大点数（数千特征点 x 30次迭代）场景下显著影响性能。

修复：使用 float* matAptr = matA.ptr<float>(i); 获取行指针后直接访问：matAptr[0] = arz; matAptr[1] = arx;，可减少约 50% 的循环耗时。
